# 0.3.0 用户体验修订

用户已授权按其问题清单实施。目标是减少第一次使用的困惑：先选择真实履约场景和门店，再谈完整一餐，最后明确展示能做与未确认的部分。

采用现有标准库实现及规则审阅器，不引入账号服务器或支付功能。优先实现偏好、真实选项、渠道一致性、会员只读和明确失败路径；全面商城、活动与订单复购放在后续。

数据从官方查询进入菜单/特调/渠道解析，整单核价进入统一 review。网页仍用脱敏历史快照，不能携带私人 Token；本地 CLI 和 WorkBuddy MCP 负责实时查询。营养保留连续指标和多维取舍，不造健康评分。偏好只有用户点击后才保存在浏览器本地。

验收：错误渠道组合在请求前拒绝；冰量用 selectedKey；去配料包含未选 key 并令营养未知；会员分页与脱敏；新条件使旧选择失效；Python/JS 偏好筛选一致；市场包解压后默认演示可运行。正向网络验证和受营业时间/供应限制的验证分别记录。

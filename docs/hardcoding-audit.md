## 保留并明确边界

| 代码中的固定值 | 原因与限制 |
|---|---|
| `catalog.py` 已核验餐品编码及属性 | 它是有限的分类依据，不能把陌生编码猜成主食、薯条、无糖或不辣。仍未支持全菜单；后续需按真实详情扩充。 |
| 三轮套餐，每轮一项 | 当前构造器的能力边界；单品、四件套、早餐和多人餐必须单独适配，不能放宽校验冒充支持。 |
| 官方业务枚举与特调字段 | MCP 协议约定，运行时读取当前选项与 key；不能通过随机值“去硬编码”。 |
| 预算初值 35 元、快捷金额 | 可修改的演示起点，不是门店定价或预算上限。 |
| 默认 15 分钟复核窗口、8 MB 响应上限 | 已有配置入口；未知/超时/超限停止，不截断后继续决策。 |
| 每轮最多 12 份候选 | 控制联网核价范围，明确报错，不隐藏截断或承诺全菜单最低价。 |
| 历史 fixtures 中门店、价格、餐品 | 是带来源与时间的实测记录。实时路径不自动回退，不将换店解释成旧报价适用。 |
| 营养按官方完整餐品名称匹配 | 改名或缺失会显示未知。尚无已验证的稳定营养编码映射，不能猜测匹配。 |

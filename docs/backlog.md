# 体验改进清单

## 本轮已落地（0.2.1）

- P0 数据来源：默认来自官方真实核价的历史快照，非编造数据。CLI（含 JSON 的 stderr）和网页显著提示非实时、门店、时间及 `--live` 入口。合成输入不会保存成官方历史快照。
- P1 用券：默认无券；新增可用券名称和匹配候选查询，显式按名称核价。无适配券时明确说明，不要求普通用户寻找 ID。真实用券成功仍未验证。
- P2 营养表达：上限保留为用户筛选条件；展示连续的钠、能量、蛋白质数据。缺少膳食纤维等完整指标及适用评分依据，因此不做任意 0–100 健康评分。
- P2 搭配取舍：对已经核价的候选给出价格/钠、口味/钠两组非支配选择，不以单一角色意见代替用户决定。当前只遍历候选，不宣称全菜单最优。

## 后续待办（尚未实现）

- P3 偏好矩阵：含糖/无糖、冰量、辣度、酱料、份量与儿童餐玩具。必须有官方可选项与数据依据，区分可核价选项、用户偏好和未知信息。
- P3 门店入口：搜索、用户授权的位置附近推荐、多门店对比。CLI 默认门店只是已验证样例；Skill 已要求先选门店。随机推荐仅在用户选定范围内进行。
- P3 分类与可配置边界：用明确产品分类替代“薯条”中文名称判断；使本工具 15 分钟复核窗口可配置；按实际大菜单需求评估响应大小。
- P3 大响应：现有 8 MB 上限是报错停止，不是静默截断或继续使用残缺菜单。新增上限或分页前先验证官方协议能力。
- P3 更多组合：先生成官方支持的完整套餐，再逐一核价，以预算和调用次数控制比较范围，避免用单品标价手算整单价。

优先验证真实用户是否能理解并完成“选门店 → 看数据来源 → 比较取舍 → 自己选择”，再扩大功能范围。
